# 优化与验证技巧

SKILL.md 第 4 到第 7 步的细化。读这份文档的时机：起草图标之前（看"优化"部分），以及迭代或验收卡住的时候（看"验证"部分）。

## 优化：画质

### 每种材质三个色调

每种材质用三个色调：基色、暗部、亮部。暗部取同色相，亮度降 15% 到 20%，饱和度略升；亮部用白色描边，不透明度 0.45 到 0.8。光源固定在左上，整套统一。

| 层 | 做法 | 位置 |
| --- | --- | --- |
| 基色 | `Icon.shape(geom, BASE, ...)` | 整个形状 |
| 暗部 | 作为 `shade` 传入的 `sh(d, SHADE, .6~.9)`，会自动裁剪到形状内 | 右下侧的一条，或底部一弧 |
| 纹理 | 作为 `shade` 传入的 `ln(..., SHADE, .8~1.2, .5~.9)` | 草编交叉线、木纹、瓦片行、砖缝、斑点 |
| 高光 | `hl(d, 1.2~1.8, .45~.8)` | 左上边缘内侧一笔短弧，不要描满整圈 |

纹理放在裁剪组里，可以随手画得超出边界，裁剪会把多余部分切掉。这比按轮廓精确计算省事得多。

有一套现成的田园调色板可作起点（pastoral 主题用的就是它）：

| 材质 | 基色 / 暗部 |
| --- | --- |
| 草、麦 | `#EDCB7A` / `#D3A752`，亮部 `#F8E2A6` |
| 金 | `#EBB23E` / `#C98E28` |
| 橙 | `#E8863A` / `#C66A24` |
| 陶土 | `#CF7448` / `#AD5634` |
| 红 | `#BF5340` / `#97402F` |
| 叶 | `#93B45A` / `#6F9442`，深色 `#557A35` |
| 木 | `#B88352` / `#93633A`，深色 `#6E4A2E` |
| 天蓝 | `#9CC5D6` / `#77A7BC` |
| 粉 | `#F0B0A4` / `#D88C80` |
| 奶油 | `#FFF6E2` / `#EBD9B6` |

新主题要换一套自己的调色板，但"三个色调、低饱和、整套统一"的规矩不变。

### 线宽分级（80 画布）

| 用途 | 线宽 |
| --- | --- |
| 外轮廓 | 2.0 到 2.4 |
| 内部结构线、小部件轮廓 | 1.1 到 1.6 |
| 纹理和细节 | 0.8 到 1.2 |

细于 0.8 的线，在 80px 下会糊成一片噪点。描边类部件（提手、茎、杆）用 `tube()`：底下一层 currentColor 粗线，上面一层窄色线，看起来是带轮廓的管子，不用画两条平行线。

### 构图

- 内容框放在 6 到 74 之间。有地面的图标，地面线或阴影统一落在 y 70 到 73，排成一页时底边对齐。
- 每个图标加一个落地锚点：低透明度阴影椭圆，或地面线配两簇草。不然图标看起来是悬空的。
- 宽而矮的物件（帽子、面包）放在视觉中心，不要贴着几何中心，通常略低一点。
- 每个图标给 1 到 3 个"小惊喜"细节，比如叶子上的瓢虫、稻草人手臂上的乌鸦、牛脖子上的铃铛。多了就显得杂。
- 场景类图标（日出、风景）用圆形取景加裁剪，再给一段虚线天空弧，不要画整块天空色。整块天空在检查里算底板，也会遮住页面背景。

### 动画调参

| 类型 | 幅度 | 时长 | 动的部件 |
| --- | --- | --- | --- |
| float | 1.8 到 2.6 px | 2.8 到 3.6 s | 烟、漂浮物、整件轻物 |
| sway | 2 到 5° | 3.4 到 5 s | 枢轴在根部或挂点（茎根、绳端） |
| spin | 无 | 10 到 24 s，匀速 | 风帆、花瓣、光芒，必须以轴心对称 |
| pulse | 1.02 到 1.04 倍 | 2.6 到 3.4 s | 呼吸感的主体 |
| pop | 1.6 到 2.2 px | 2.8 到 3.8 s | 弹起，底边作枢轴 |

- 一套里每个图标的时长都错开 0.2 到 0.4 秒，否则排成网格时会整齐划一地同步摆动。
- 大件的幅度取下限，小件取上限。

### 文件大小

- 坐标统一保留 1 位小数（用 `f()`）。
- `stroke-linecap` 和 `stroke-linejoin` 写在根元素上，子元素会继承。
- 同色同宽的线合并成一条多段 `M` 的 path。
- 重复的图案（麦穗、花瓣、栅条）先在 `<defs>` 里定义一个 `<g id>`，再用 `<use>` 复用几次，每个复用可以带不同的 transform。
- 纹理里的随机数用固定种子（`random.Random(7)`），每次重新生成结果都一样，前后对比才可信。

## 验证：从便宜到昂贵逐层做

前一层没通过，就不要往下走。

1. **静态校验**：`validate-static.mts`，几秒钟。它报出的每一条都是硬错误，修完再跑一遍。
2. **总览图**：`sheet.mjs` 用 130px 看全套，再用 280px 每批 4 个看细节。必须用 Read 工具打开 PNG 亲眼看，不能凭脚本"通过"就算数。
3. **小尺寸辨认**：`sheet.mjs <dir> out.png 48`。在 48px 下认不出是什么，说明剪影太弱，需要加粗外轮廓、减少内部细节、拉开明暗对比。
4. **跟随色压力测试**：`INK=#e5484d node sheet.mjs <dir> ink.png 130`。变红的部分会跟随页面取色器，其余是固定色，逐项核对：
   - 外轮廓应该全红。
   - 不该出现大块红色。出现了，就是误用了 currentColor 填充。
   - 在深色那一行，轮廓缺口会很明显。
5. **动画帧条**：`filmstrip.mjs <dir> film.png 120 [ids]`，把每个动画按 8 个相位从左到右排开，红色虚线框是 3 个单位的安全边。逐行检查：
   - 枢轴对不对。根部应该不动，挂点应该不动。
   - 是不是只有该动的部件在动。
   - 有没有越过虚线框。
6. **浏览器验收**：`validate-browser.mjs`，覆盖动画数、暂停和恢复、减少动态、8 个相位的边距、双尺寸双背景、错误与外部请求。边距失败时报告里有失败相位和四边数值，按"左、上、右、下"的顺序读，就知道该收哪一边。
7. **前后对比**（重绘时）：对原稿目录和新目录各跑一次 `sheet.mjs`，用同一个 cell 大小，然后并排看。确认三点：
   - 主体还是原来的东西。
   - 新图在质感上明显更好。
   - 没有图标退步：剪影变弱，或在深色背景下变脏。
8. **仓库校验**（种子主题）：`npm run check:svg-kits && npm run build`。
9. **线上核对**：
   - URL 加 `?t=$RANDOM` 绕过缓存。
   - 用 Playwright 滚到底，统计已渲染的 shadow SVG 数量是否等于件数。
   - 打开一个新图标的详情弹层截图。详情弹层不用 shadow root，作用域问题只会在这里暴露。
   - R2 主题还要分别带 Origin 头和不带 Origin 头各请求一次 CDN，确认两份缓存都已更新。

## 常见问题怎么修

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 部件压在不该压的东西上（门柱在横栏后、车轮盖挡泥板） | 绘制顺序 | 按"后、中、前"重排。动画组不能拆开时，就把静态件画在动画组之前，并缩短会被遮住的部分 |
| 形状在边缘被平切，像悬崖 | path 终点直接落在地面 | 终点前加一段向下收的曲线，让形状自然收进地面 |
| 装饰件被看成别的东西（光芒像旗子） | 与邻近元素同色、同尺度、同方向 | 抬高遮挡物（如山丘），或缩短、换位置，或改颜色 |
| 小部件悬空 | 坐标估算偏了 | 用 280px 截图逐个对准宿主的边缘或表面 |
| 弹跳峰值顶到边 | 位移叠加了缩放 | 降低幅度，或缩短最高的部件（耳朵、尖顶）1 到 2 个单位 |
| 深色背景下发脏、发灰 | 阴影或深色细节和 `#1c1d24` 太接近 | 浅色化，或在暗色上加一圈 currentColor 细轮廓 |

## 汇报

只写实际测到的数字和结论：

- 件数（新增多少）、最大字节和元素数。
- 最小边距，以及是哪个图标。
- Chrome 版本、错误数、外部请求数。
- 前后对比的结论。
- 提交号或发布结果、线上件数。

没跑的检查就写"未跑"。没过的检查就写哪一步没过，不要用"应该没问题"代替结果。
